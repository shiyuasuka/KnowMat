# 有界折线图上下文设计

日期：2026-08-17

## 目标

在保留纯代码折线图逐点数字化精度的前提下，保证任何单图或多图论文都不会因为逐点 CSV 注入 Markdown 而显著放大 Alpha25 的 LLM 上下文。

## 现状基线

人工标注集共有 15 张可评测图。当前纯代码结果包含 3,651 个点：若全量内联，合计 110,247 字符，单图最高 21,369 字符；生产路径在 CSV 正常落盘时只注入文件引用，但落盘失败会回退为全量内联，缺少硬性单图和单篇预算。

## 方案

### 数据层

- 完整逐点数据继续写入每图 long-format sidecar CSV。
- 不降低 PDF vector/raster code 的采样精度，不让 VLM 生成或修改坐标。
- CSV 写入失败时只降级上下文表示，不把完整点表内联。

### 单图上下文层

每条序列仅暴露有证据价值的确定性摘要：

- 序列标签、类型和原始点数；
- 起点、终点；
- Y 最小值、Y 最大值；
- X 中位附近代表点；
- 完整 CSV 相对路径（成功落盘时）。

摘要按原序列顺序生成，去除重复代表点。默认最多展示 12 条序列，并使用 2,400 字符的单图硬上限；未展示序列只报告数量，不伪造统计。

### 单篇上下文层

所有 chart block 共享默认 12,000 字符预算：

- 预算足够时保留单图摘要；
- 预算不足时降级为图号、坐标轴、序列/点计数和 `data_csv` 引用；
- 连最小引用块也无法容纳时不注入该图，但 sidecar CSV 仍保留；
- 普通图像的 prose description 不计入折线图预算，由其现有策略管理。

预算通过 `KNOWMAT2_CHART_CONTEXT_MAX_CHARS_PER_FIGURE`、`KNOWMAT2_CHART_CONTEXT_MAX_CHARS_PER_PAPER` 和 `KNOWMAT2_CHART_CONTEXT_MAX_SERIES` 配置；非法值回退到安全默认值。

## 失败与安全规则

- sidecar 写入失败必须标记 `data_csv: unavailable`，不得恢复全量内联。
- 上下文摘要只读取代码生成 CSV 中已有的坐标，不推导新数值。
- 可选 VLM 只能补充标签或分类，不能改变摘要所引用的坐标。
- 格式器输出必须满足配置的字符上限；多图注入总量必须满足单篇上限。

## 验证

1. 单元测试覆盖 sidecar 成功、sidecar 失败、长序列、超多序列和多图累计预算。
2. 现有 vector/raster/figure pipeline 回归全部通过。
3. 在 15 张人工标注图上复跑，趋势、边界、marker/spread 指标不得下降。
4. 统计全量 CSV、单图摘要和单篇注入字符数，证明硬上限真实生效。
5. 对当前 30 篇 PDF 的真实 chart candidates 执行只读生产路径测试，记录成功、降级、失败和上下文大小。

## 非目标

- 本次不改变 Alpha25 材料身份归并、GT 匹配或属性 schema。
- 不删除完整折线点，也不将 GT 用于生产抽取。
- 不把 sidecar CSV 的全部内容自动拼回主论文 Markdown。
